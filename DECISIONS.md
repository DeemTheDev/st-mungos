# Decisions

- **2026-08-12 · Name: St Mungo's** — the wizarding hospital; she's training to be a Healer. Subdomain of accioazra.com.
- **2026-08-12 · Examiner/marking/case-gen model: `claude-sonnet-5`** (brief said sonnet-4-6; Sonnet 5 is newer, same tier, intro-priced $2/$10 per MTok through 2026-08-31 — the exact build window). Patient stays `claude-haiku-4-5`.
- **2026-08-12 · Disclosure is engine-gated, not prompt-trusted**: the session engine matches student utterances against fact `triggers` and injects only volunteered + already-triggered facts into the patient model's context. The patient cannot leak what it never saw; prompt rules remain as defense-in-depth. Trigger lists are generated deliberately fat (synonyms, lay phrasings).
- **2026-08-12 · Persistence: dedicated Supabase project** (not the Teapot's) — different trust model (APP_ACCESS_PASSWORD gate + service-role from API routes vs two-user RLS). Until the project exists, the store port has a local JSON-file adapter so dev is unblocked.
- **2026-08-12 · KB pipeline runs as local CLI for Phases 1/5** (no serverless limits, incremental via manifest); the same `lib/kb-pipeline/` runs as a background job for Phase 6 uploads.
- **2026-08-12 · Package manager: pnpm.** Haiku prompt-cache note: Haiku 4.5 minimum cacheable prefix is 4096 tokens — patient system prompt (persona + case) must clear it, verify `cache_read_input_tokens > 0` in dev.
- **2026-08-12 · /grounding is gitignored entirely** (her private course material). The distilled KB's storage is Supabase (runtime-updatable, §5d); repo keeps only pipeline code.
- **2026-08-13 · Admin review gate: hashed-password cookie, no session store.** `/admin/review` and its API routes check an httpOnly cookie holding `sha256("st-mungos-admin:" + APP_ACCESS_PASSWORD)`; login is a plain form POST to `/api/admin/login`. Rotating the password invalidates every cookie. Timing-safe compares throughout; the page itself is all server components + plain HTML forms (works with zero client JS).
- **2026-08-13 · Draft ids are assigned in code, not by the model** — `<system>-NNN-<diagnosis-slug>` (clinical) / `interp-abg-NNN-<slug>` (interpretation), NNN sequenced across bank + drafts. The generator also enforces a code-level dedupe on normalised diagnosis and refuses to overwrite existing draft files.
- **2026-08-13 · ABG stations: values are computed and validated in code (`lib/abg.ts`), never by the LLM.** Nine scenario archetypes sample physiologic parameters, pH is derived from Henderson-Hasselbalch on the rounded values, and every gas must pass deterministic checks (H-H ±0.03, Winter's ±2 mmHg, acute ≈1 / chronic ≈3.5–4 mmol per 10 mmHg compensation deltas, anion gap range). Sonnet only wraps the numbers in the case JSON; if it edits any value the code restores the originals.
- **2026-08-13 · Generator prompt caching:** the static block (instructions + seed case + KZN epidemiology brief) rides in `system` with `cache_control: ephemeral`; per-case content (KB topic) rides in the user message — calls 2..N of a run read the cached prefix.
- **2026-08-13 · Generators use structured outputs + no thinking + MAX_TOKENS 8000.** `output_config.format` (zodOutputFormat via `client.messages.parse`) makes the JSON shape API-enforced; refine rules (rubric sum, trigger fatness) stay as the client-side safeParse+retry backstop. Generation is JSON transcription, so `thinking: {type:"disabled"}` and the budget drops back to 8000. Caveat: structured outputs forces `additionalProperties:false` on every object, so open-key records can't be generated directly — the clinical generator asks for `pathophys` as an array of `{symptom, mechanism}` pairs (converted to the record in code) and fills `examination.other` with `{}`.
- **2026-08-13 · Target diagnosis is picked in code, not by the model.** `scripts/diagnosis-pool.ts` holds a per-system, KZN-weighted pool (common/uncommon, with topic-match keywords); the generator excludes bank+drafts diagnoses up front and pins the pick in the prompt — no generation is ever wasted on a dedupe collision. Pool exhausted → the run stops early with a message.
- **2026-08-13 · Phase 2 session engine is deterministic; the Brain is a port.** `lib/session-engine.ts` owns disclosure gating (trigger match: word-boundary + stem tolerance), exam-step → findings narration, verbatim investigation results (stimulusRef pauses into an interpret-step), phase transitions, speaker arbitration, bank triggers, the 20:00/7:00 timers (accumulated ACTIVE seconds — away-time after quit never counts), nudges and warnings. `BRAIN=mock|live` (default mock) picks the Brain: MockBrain is fully deterministic (template patient speech, verbatim examiner lines, a real computed MarkingReport from the tracked logs) so the whole flow runs and is tested at $0 (`pnpm simulate`); AnthropicBrain (haiku patient w/ padded cached rules block, sonnet-5 examiner follow-ups + single structured-outputs marking call) is code-complete and awaits API budget.
- **2026-08-13 · Session persistence: STORE=file|supabase, default file.** `.sessions/*.json` (gitignored) for dev; `st_sessions (id text pk, data jsonb, updated_at)` via `SUPABASE_URL`+`SUPABASE_SECRET_KEY` for prod — DDL in `supabase/schema.sql`. New env vars: `BRAIN`, `STORE`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`.
- **2026-08-13 · /session reuses the /admin/review cookie gate** (single user, single password); `/api/admin/login` now accepts a same-site `next` path so both pages can bounce back after login. The client only ever receives a redacted SessionView — the hidden case JSON never ships to the browser.
- **2026-08-13 · Voice architecture (Phase 3): Azure SDK behind the §3 ports, loaded on demand.** `SpeechToText`/`TextToSpeech` live in `lib/ports.ts`; the Azure adapters in `lib/speech/` are reached only via `createVoiceSession()`, which the station dynamic-imports when "🎙 Enable voice" is pressed — the ~1 MB SDK and every voice failure mode stay entirely out of the text-mode path. STT builds a **fresh recognizer per push-to-talk hold** (each hold re-checks the token provider, so there is no stale-auth state to manage), recognition language `en-ZA`. TTS voices follow the case patient's sex (F→`en-ZA-LeahNeural`, M→`en-ZA-LukeNeural`; examiner always the other voice) and are sequenced by a `SerialQueue` on **`SpeakerAudioDestination.onAudioEnd` — actual playback end** — because the SDK's own completion fires when audio *bytes* are delivered, long before the speaker goes quiet; sequencing on that would let the examiner talk over the patient. A per-utterance watchdog (`max(15s, 150ms/char)`) stops a wedged playback from jamming the queue, and holding to talk barges in (cuts playback) so she never talks over the TTS.
- **2026-08-13 · Speech token TTL 540s, client refresh at 8 min.** Azure STS tokens live 10 minutes; `/api/speech/token` (nodejs, same admin cookie gate) advertises `expiresInSec: 540` and the browser `TokenProvider` re-fetches once a cached token is ~8 minutes old — or immediately after a 401-type SDK failure (`invalidate()`). The route and `scripts/verify-speech-token.ts` share one `issueSpeechToken()` (`lib/speech/token-server.ts`), so the code path verified against the real eastus endpoint IS the deployed one. Azure error bodies are never forwarded (status-code-only messages) — no header/key material can leak; the key itself never leaves the server (CLAUDE.md §2.4).
- **2026-08-13 · Voice fallback policy: text mode is the floor, never blocked.** Voice starts OFF every session. Enabling runs mic permission → token fetch → SDK load, in that order, and any failure = console.warn + dismissible notice chip + station stays in text mode. At runtime: STT drops → notice, the next hold retries with a fresh token; TTS failure → notice (the reply is always in the transcript anyway), **two consecutive** TTS failures → voice auto-switches off. Mute skips lines rather than stockpiling them (repeat-last covers the one that mattered). The text input stays rendered and functional whether voice is off, enabling, or on.
- **2026-08-13 · Shared nav; management focus is a session mode.** `components/site-nav.tsx` takes the active route as a prop (server component, zero client JS) — landing on prod used to dead-end with no route to `/session`. `SessionState.mode: "full" | "management"` (§8): management mode opens in the `management` phase, seeds an examiner line naming the diagnosis, caps the clock at 10 min, and makes the examiner the default responder. Ignored for interpretation stations; sessions persisted before the field read back as `"full"`.
- **2026-08-13 · Marking is deliberately NOT mode-aware.** A management viva is still marked against the whole `stationChecklist`, so history/exam rows come back missed and the score is not comparable. `/notes` therefore excludes management vivas from mean score, band distribution and most-missed, and both the picker and notes page say so. Making marking mode-aware means changing `lib/brains/*` — deferred.
- **2026-08-13 · PDF export is the browser's print pipeline, not a PDF library.** `/notes/print` stacks every report with an `@media print` block (one report per page, sub-blocks never split) + `window.print()`. No jsPDF/@react-pdf — the export tracks the real markup instead of a second hand-maintained layout.
- **2026-08-13 · MockBrain has a conversational floor; the information model does not change.** Openers, repeat requests and bare acknowledgements used to hit `"I'm not sure, doctor."` Resolution order after the matched-fact branch: repeat → opener → greeting → acknowledgement → rotated fallback. `onAsk` gating is untouched — the opener restates only the spoken opening line plus `volunteered` facts, and the written `presentingComplaint` is appended only when `leaksHiddenTopic()` proves it matches no still-hidden trigger (it names gated topics in most cases, so it is usually suppressed). Fallbacks rotate by patient-turn count — no RNG, so `pnpm simulate` stays reproducible. The Haiku patient prompt states the same contract, and the per-session persona block is gated by the same check (evaluated against ALL `onAsk` facts so the cached block stays byte-identical).
- **2026-08-13 · Voice names are server config, not code.** `VOICE_PATIENT_F` / `VOICE_PATIENT_M` / `VOICE_EXAMINER` resolve server-side and ride on `/api/speech/token` as `voices`; the TTS adapter resolves per utterance, so a Vercel env change swaps voices within one token refresh (≤8 min), no redeploy. SSML is tuned per voice generation from the live catalogue: classic neural voices get `prosody rate="-5%"` + 250 ms sentence breaks; HD/MAI voices get plain text (they model prosody themselves); styles only for voices the API reports as style-capable — Leah/Luke are `StyleList: none` and never receive one. **eastus has exactly two en-ZA voices, both first-generation: there is no more natural SA voice**, so every upgrade trades the accent. Recommended compromise: keep Leah/Luke as patients, pin `VOICE_EXAMINER=en-GB-Ollie:DragonHDLatestNeural` (the examiner carries the long clinical narration).
- **2026-08-13 · Phase 4 room: r3f 9.7 + drei 10.7 + three 0.185, dynamic-only.** Reached solely via `next/dynamic({ssr:false})`, so three never enters the server bundle and its 961 kB chunk is absent from `/session/[id]`'s initial set. Two lights, primitives for the bed, no post-processing. **Model: meshopt + 1K WebP, not Draco** — 17.86 MB → 948 kB (18.8×); Draco was rejected because drei's `useGLTF` fetches its decoder from `gstatic.com`, while the meshopt decoder ships in `three-stdlib` (zero third-party runtime requests). Geometry is normalised at runtime (bbox → 1.75 m, feet at y=0), so a replacement `.glb` needs no code change.
- **2026-08-13 · The 3D room is opt-out decoration.** `localStorage["st-mungos:ward-scene"]`, default ON only on desktop-width viewports with WebGL and no `prefers-reduced-motion`. Read via `useSyncExternalStore` (no hydration mismatch). Every station function works identically with the scene off.
- **2026-08-13 · `SessionView` now carries the stimulus (bug fix).** `toSessionView` was dropping `stimulus`, so interpretation stations had nothing to show the student — the stimulus is the point of those stations. Now exposes `{kind, vignette, values, imagePath}` for interpretation cases only; `findingsKey`, `interpretationChecklist`, `examinerBank`, `diagnosis`, `management` stay server-side.
- **2026-08-13 · One "who's speaking" stream for both modes.** Examiner bubble and patient bob consume `speaking ?? textCue` — real `SpeakingEvent`s when voice is audible, and in text mode a synthetic cue from the turn's replies (`clamp(2.5 s, 45 ms/char, 9 s)`). Subscribed once in `station-client` — `TextToSpeech.onSpeaking` has no unsubscribe, so a second subscriber would leak.
- **2026-08-13 · `.env.example` un-ignored.** `.gitignore`'s `.env*` swallowed the template, so a fresh clone had no env reference at all (CLAUDE.md §12 asks for README/env parity). Added `!.env.example`.
- **2026-08-16 · The room is deleted; the patient tile is a portrait over CSS.** The r3f scene now contains one figure, four lights and a transparent canvas — no backdrop, floor, bed, cabinet or drip stand. The tile background (studio wash, 5.5% grid, floor pool, vignette) is CSS, so it costs nothing, themes without touching three, and stops boxing the camera in. Deleting the walls also removed the absolute 5.8 m zoom clamp: orbit distance is now relative to the solve (0.6×–1.4×).
- **2026-08-16 · Camera framing is solved and PROVEN, not guessed.** `components/ward/framing.ts` normalises the .glb (bbox → 1.75 m, feet at y=0, centred) and solves camera distance by fixed-point iteration on projected NDC extents — a closed-form fov formula undershoots because the camera is off-axis and pitched. `lookAt` is the bbox centre (y=0.875 m, chest), never the origin: aiming at the origin is what produced "you can only see his boots". `pnpm verify:framing` loads the real .glb headlessly with the meshopt decoder, applies the same normalisation and fit, and asserts all 8 bbox corners inside ±0.94 NDC with 60–85% vertical fill across 7 tile aspects (0.563–3.170). It lives beside framing.ts, not in scripts/, so it changes in the same commit as the constants it proves.
- **2026-08-16 · The station is a bento grid; the transcript is the only scroller.** Chat column 54% / presence column 46% on ≥1024px; everything else is fixed-height, which is why there is no dead space to accumulate (measured: 12px, the grid padding). DOM order is presence-then-conversation with `lg:order-*`, so mobile stacks correctly without a JS breakpoint. The patient tile is `hidden lg:block` unless 3D is explicitly on — a phone's vertical budget belongs to the conversation. Print hides the live transcript and prints the report only (it previously printed light-on-light and was unreadable).
- **2026-08-16 · `--station-vh` is driven by a ResizeObserver, and never written as zero.** `visualViewport.resize` catches the mobile keyboard but does NOT reliably fire on a layout-viewport change, leaving a stale height and dead space; a `ResizeObserver` on `documentElement` catches that. A transient zero reading beats the `100dvh` fallback and collapses the whole station permanently, so zero is never written.
- **2026-08-16 · Patient voice is user-selectable, random-by-default, deterministic per station.** Precedence: `VOICE_PATIENT_F`/`VOICE_PATIENT_M` env pin (disables the picker for that sex) → her dropdown choice (`localStorage["st-mungos:patient-voice"]`, must be in the pool) → `FNV-1a(sessionId) % pool.length`, stepped off a collision with the examiner. Deterministic by construction: `Math.random()` at render time would re-cast the patient mid-station and again on resume. Sex-aware pools are env-configurable via `VOICE_PATIENT_POOL_F`/`VOICE_PATIENT_POOL_M` (comma-separated) and ride on `/api/speech/token` with the pins; the client ships the same defaults so the picker works before voice is ever enabled. Examiner behaviour (`VOICE_EXAMINER` ?? opposite shipped voice) is unchanged. `TextToSpeech` gained `setPatientVoice()`, resolved per utterance, so both an env change and her picker land without a reload.
- **2026-08-16 · Station UX for a timed exam:** clock tile (tabular-nums, amber ≤2:00, red+pulse ≤0:30, elapsed rail) · phase rail showing the engine's state machine (previously invisible) · phase-scoped quick-action chips that INSERT into the composer and never send, worded to match the engine's own intent regexes · scroll integrity (opens at newest, "N new ↓" pill instead of yanking her back mid-reread) · `Esc`/`?` only, plus aria-live on the newest reply. Deliberately few shortcuts — more keys is more to hold in her head during a timed station.
- **2026-08-17 · Flashcards backend: 3-pass Haiku pipeline, one step per invocation.** `lib/flashcards/` — survey → windowed extraction (~3k-token windows, 15% overlap, answer-key slices paired by qnum in code) → reconciliation (deterministic qnum/prefix matching, then ONE cleanup call that outputs id-pairs only — the model never writes answer text, so a bad match can mispair but never invent). Model `claude-haiku-4-5-20251001`, structured outputs (`messages.parse` + zodOutputFormat), thinking disabled. Job state + checkpoint live on the `fc_documents` row; a killed job resumes at the last completed window; scans are detected and refused. Cross-window dedupe = unique(document_id, qhash) on the normalised question. Real-data run: 61-page mixed-layout PDF → 797 cards ($0.52); 27-page MCQ docx → 218 cards ($0.21); $0.73 total.
- **2026-08-17 · Flashcards storage: FcStore port, STORE=file|supabase; RLS with no policies.** Same env switch as sessions. Supabase: 4 `fc_*` tables (`schema-flashcards.sql`), FTS via a generated tsvector over topic+question+answer, raw uploads in a private `flashcards` Storage bucket. File adapter under `.flashcards/` (gitignored) keeps dev and `pnpm fc:test` at zero services.
- **2026-08-17 · FSRS via ts-fsrs, fuzz off; EXAM_DATE cram cap; day-seeded interleave.** Grades again/hard/good/easy → `fsrs().next()`. `EXAM_DATE` (YYYY-MM-DD, local end-of-day — never toISOString) caps due dates while the exam is ahead. Review queue: due-today first, round-robin across topics ordered by FNV-1a(dayKey:id) — stable within a day, reshuffles tomorrow. needs_review cards never enter the queue.
- **2026-08-17 · Flashcards PWA service worker is hand-rolled, not @serwist/next.** Serwist injects its manifest through a webpack plugin; this app builds with Turbopack, so the plugin never runs. `public/sw.js` + `app/manifest.ts` instead: app-shell precache, network-first for HTML/API, cache-first for static assets. Grading deliberately does NOT work offline — a queued grade would corrupt the FSRS schedule silently, so the UI fails honestly instead. `start_url` is `/flashcards`, so the installed icon opens the study tool, not the landing page.
- **2026-08-17 · The flashcards UI distinguishes "backend absent" from "backend broken".** The typed client throws `FlashcardsUnavailableError` (routes/tables not deployed yet) vs `FlashcardsApiError` (deployed and erroring), rendered as two different friendly states. Deploy order can therefore never produce a page that merely looks broken.
- **2026-08-17 · Case generation survives the structured-outputs grammar limit.** The API began rejecting the full clinical case schema with 400 "The compiled grammar is too large" (the interpretation schema still compiles). `generateStructured` catches that one error, remembers the schema in a WeakSet so later calls skip the doomed probe, and falls back to a plain call demanding MINIFIED JSON (pretty-printing burns ~40% more output tokens; FALLBACK_MAX_TOKENS 12000) validated client-side with the SAME Zod schema and the same feedback-retry loop. If the API limit ever rises the probe succeeds again and structured outputs resume automatically. Every call now logs tokens + running $ (`logUsage`).
- **2026-08-17 · Prompt caching on the patient turn was silently OFF; now measured and asserted.** Haiku 4.5 ignores `cache_control` on any prefix under 4096 tokens, without warning — the rules block measured **3401 tokens**, so every patient turn re-paid full input price while the code comment claimed it was "padded well past" the floor. Extended with genuinely useful material (unusual phrasings, compound questions, ICE, misheard-detail correction) to **4192 tokens**. Measured effect per patient turn: input 3643 → 118, with 4316 tokens cache-read from turn 2 on (~85% off input). Lesson: a caching claim that is not asserted is a guess — `pnpm e2e:live` now fails if cache_read is 0.
- **2026-08-17 · `pnpm e2e:live` — the one script that spends money, and the only proof of the disclosure guarantee.** Two live stations (clinical: Haiku patient + Sonnet examiner + Sonnet marking; interpretation: examiner + marking). Its central assertion cannot be made against MockBrain: run A never asks about HIV, so hx-hiv never matches a trigger, so the patient model is never sent that fact — and a real model that *would* happily improvise stays silent. Also asserts marking flags the un-asked item as missed rather than hallucinating coverage, both reports satisfy MarkingReportSchema, and the cache is live. Run B points at `cases/drafts` on purpose: the bank holds no approved interpretation station yet.
- **2026-08-17 · Phase 6 — the pipeline moves server-side; Supabase becomes the source of truth.** Until now the KB (`grounding/kb/*.md`) and the case bank (`cases/{drafts,bank}/*.json`) lived only on Nadeem's laptop, so uploading a guide, distilling it, generating a station and approving it were all local operations and production could merely REPLAY whatever had been committed to git. `supabase/schema-library.sql` adds `st_source_docs`, `st_kb_topics` (generated tsvector + GIN), `st_cases` (status draft|bank|rejected) and `st_spend`; `lib/library/types.ts` defines the ports. Git files become a one-time seed pushed by `pnpm migrate:library`. Decisions taken with Nadeem: Supabase is the source of truth, Azra reviews in the main app (not `/admin`), generation is a deliberate button press, and spend has hard caps.
- **2026-08-17 · Library storage: `Library` port, STORE=file|supabase, the same switch as everything else.** `getLibrary()` returns `FileLibrary` (docs → `.library/`, kb → `grounding/kb/*.md` + `_index.json` in FsKbStore's exact format, cases → `cases/{drafts,bank}` with setStatus moving the file, spend → `.library/spend.jsonl`) or `SupabaseLibrary` (four `st_*` tables + a private `grounding` bucket). File mode keeps the library-only columns in `.library/{kb-meta,case-meta}.json` sidecars, because `pnpm distill` rebuilds `_index.json` from scratch and `OsceCaseSchema` strips unknown keys — anything stored inline would be silently lost.
- **2026-08-17 · Production plays from `st_cases WHERE status='bank'`, and that filter is unbypassable.** `SupabaseCaseStore` implements the read-side `CaseStore`; every query is built by one of two private methods that pin `.eq("status","bank")`, no method accepts a status or table, `get()` re-asserts the status on the returned row so a loosened query still fails closed, and rows are re-validated against `OsceCaseSchema` (a corrupt row is hidden, never half-played). Proven with a fake client that ignores filters — `get()` still returned null. The write/review side is a separate port (`CaseLibrary`), which is what makes "unreviewed cases never reach the student" (CLAUDE.md §2.3) structural rather than conventional.
- **2026-08-17 · The case generator is a library, not a script.** Prompts, the KZN diagnosis pool, `generateStructured` with its grammar-too-large fallback, and the validate-then-retry loop moved from `scripts/` into `lib/library/generate-job.ts`; `pnpm gen:cases` and `POST /api/cases/job/[id]/step` call the same `generateOneCase()`. Forking the prompt between CLI and server was the most likely way for the bank's quality guarantees to rot. Every safety property survives: diagnosis picked in code from the pool, dedupe before spending, Zod validation, id assigned in code.
- **2026-08-17 · Generation jobs are stateless; the job id IS the job.** No `st_gen_jobs` table and no jobs port: `POST /api/cases/generate` returns a base64url token carrying `{system,count,commonness,startSeq,createdAt}` and each step derives progress from the case ids that block owns. A refresh, redeploy or killed poll loses nothing, and there is no job table to keep consistent with `st_cases`. It also means **closing the tab stops the spending** — the server only works when polled, so there is no runaway job to hunt. A step whose case fails validation twice ends the job rather than looping, because a stateless step cannot remember a failed attempt and re-polling would spend money forever.
- **2026-08-17 · The budget is a hard stop before every model call, not a report after it.** `lib/library/budget.ts` checks `spend.jobTotal()` against `LIBRARY_JOB_BUDGET_USD` (2.00) and `spend.monthTotal()` against `LIBRARY_MONTH_BUDGET_USD` (10.00) BEFORE each call, books a ledger row after it, and surfaces `BudgetExceededError` as HTTP 402 with a plain sentence naming the limit and the spend so far. 402 is deliberately not an error state in the UI — the pipeline stopped on purpose, so it renders as a calm receipt. A non-numeric or ≤0 limit warns and falls back to the default; a typo must never read as "unlimited". The CLIs keep a console sink (a human is watching the terminal), so `pnpm gen:cases` output is byte-identical.
- **2026-08-17 · Upload → KB is one chunk per invocation, checkpointed on the row.** `uploaded → extracting → distilling (n/m) → ready | failed`, reusing `lib/kb-pipeline`'s splitters and the exact distil prompt that produced the existing 27 topics. The checkpoint stores the section bodies rather than the source file, because re-extracting a 300-page PDF inside every 120s invocation would be paid over and over. Transient API errors propagate with the checkpoint untouched so the next poll retries the same chunk; only scans and unsupported types are terminal. `/grounding` is gitignored and therefore absent in production, so the epidemiology brief is bundled from CLAUDE.md §1 — never from her material.
- **2026-08-17 · Review is an UPDATE, not a rename — the bug that made production review impossible.** `/api/admin/review` used `renameSync(cases/drafts/x.json → cases/bank/x.json)`, which cannot work on Vercel's read-only filesystem. Both the form endpoint and the new `POST /api/cases/[id]/review` now call `CaseLibrary.setStatus`. Rejection sets status `rejected` (kept for the audit trail) rather than deleting, and approval re-validates against `OsceCaseSchema` because a case can be hand-edited between generation and approval — a 422 with a readable message is a real reviewer-facing state.
- **2026-08-17 · `/admin/review` became `redirect("/review")`, and the framing changed with the address.** The queue is now hers: section headings ask "does this hold up clinically?" instead of dumping JSON, each section carries a plain-language *check this* line, approve takes a second tap that names the consequence (it becomes playable), reject takes one. The old path stays as a redirect because `/api/admin/login`'s default `next`, the CLIs, README and her bookmarks all pointed at it — a 404 on a bookmark is worse than one hop. Those internal references now point at `/review` directly.
- **2026-08-17 · The library client distinguishes absent / broken / capped — and 404 is not "absent".** `LibraryUnavailableError` (405/501, HTML body, network) vs `LibraryApiError` vs `BudgetError` (402). A 404 is deliberately NOT treated as "backend not deployed": these routes legitimately 404 for an unknown case/topic/job, and rejecting a draft twice 404s the second time. Answering "the library backend isn't connected yet" to a double-click would send Nadeem hunting a deploy problem that doesn't exist — so a 404 *with a body* is the route talking and shows its message; only a bodyless or HTML 404 means nothing answered.
- **2026-08-17 · `pnpm migrate:library` is idempotent and never demotes.** KB topics upsert by slug, cases by id; a case already in Supabase keeps its remote status, review note and timestamp while its JSON is refreshed — re-running can never turn an approved station back into a draft or resurrect a rejected one. Every case is validated before insert (failures skipped and reported, never fatal). `--dry-run` makes zero network calls, so it works with no keys.
- **2026-08-17 · Flashcards prompt caching measured and deliberately NOT "fixed".** The three blocks are 1410 / 445 / 283 tokens, all under Haiku's 4096 floor, so `cache_control` is inert there too. Unlike the patient rules block, padding would be a net loss: a 12-window document saves ~$0.007 by caching, while each window is one client poll — a backgrounded tab blows the 5-minute TTL and a padded block then costs ~4x an unpadded one (1.25x write on 3x the tokens). The `cache_control` stays so the win arrives automatically if the floor ever drops. The real lever is OUTPUT, not input: the 1015-card run was $0.12 input vs $0.61 output, so the Batches API (50% off) is the fast-follow worth building.
