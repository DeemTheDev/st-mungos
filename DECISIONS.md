# Decisions

- **2026-08-12 · Name: St Mungo's** — the wizarding hospital; she's training to be a Healer. Subdomain of accioazra.com.
- **2026-08-12 · Examiner/marking/case-gen model: `claude-sonnet-5`** (brief said sonnet-4-6; Sonnet 5 is newer, same tier, intro-priced $2/$10 per MTok through 2026-08-31 — the exact build window). Patient stays `claude-haiku-4-5`.
- **2026-08-12 · Disclosure is engine-gated, not prompt-trusted**: the session engine matches student utterances against fact `triggers` and injects only volunteered + already-triggered facts into the patient model's context. The patient cannot leak what it never saw; prompt rules remain as defense-in-depth. Trigger lists are generated deliberately fat (synonyms, lay phrasings).
- **2026-08-12 · Persistence: dedicated Supabase project** (not the Teapot's) — different trust model (APP_ACCESS_PASSWORD gate + service-role from API routes vs two-user RLS). Until the project exists, the store port has a local JSON-file adapter so dev is unblocked.
- **2026-08-12 · KB pipeline runs as local CLI for Phases 1/5** (no serverless limits, incremental via manifest); the same `lib/kb-pipeline/` runs as a background job for Phase 6 uploads.
- **2026-08-12 · Package manager: pnpm.** Haiku prompt-cache note: Haiku 4.5 minimum cacheable prefix is 4096 tokens — patient system prompt (persona + case) must clear it, verify `cache_read_input_tokens > 0` in dev.
- **2026-08-12 · /grounding is gitignored entirely** (her private course material). The distilled KB's storage is Supabase (runtime-updatable, §5d); repo keeps only pipeline code.
- **2026-08-13 · Admin review gate: hashed-password cookie, no session store.** `/admin/review` and its API routes check an httpOnly cookie holding `sha256("st-mungos-admin:" + APP_ACCESS_PASSWORD)`; login is a plain form POST to `/api/admin/login`. Rotating the password invalidates every cookie. Timing-safe compares throughout; the page itself is all server components + plain HTML forms (works with zero client JS).
- **2026-08-13 · Draft ids are assigned in code, not by the model** — `<system>-NNN-<diagnosis-slug>` (clinical) / `interp-abg-NNN-<slug>` (interpretation), NNN sequenced across bank + drafts. The generator also enforces a code-level dedupe on normalised diagnosis and refuses to overwrite existing draft files.
- **2026-08-13 · ABG stations: values are computed and validated in code (`lib/abg.ts`), never by the LLM.** Nine scenario archetypes sample physiologic parameters, pH is derived from Henderson-Hasselbalch on the rounded values, and every gas must pass deterministic checks (H-H ±0.03, Winter's ±2 mmHg, acute ≈1 / chronic ≈3.5–4 mmol per 10 mmHg compensation deltas, anion gap range). Sonnet only wraps the numbers in the case JSON; if it edits any value the code restores the originals.
- **2026-08-13 · Generator prompt caching:** the static block (instructions + seed case + KZN epidemiology brief) rides in `system` with `cache_control: ephemeral`; per-case content (KB topic) rides in the user message — calls 2..N of a run read the cached prefix.
- **2026-08-13 · Generators use structured outputs + no thinking + MAX_TOKENS 8000.** `output_config.format` (zodOutputFormat via `client.messages.parse`) makes the JSON shape API-enforced; refine rules (rubric sum, trigger fatness) stay as the client-side safeParse+retry backstop. Generation is JSON transcription, so `thinking: {type:"disabled"}` and the budget drops back to 8000. Caveat: structured outputs forces `additionalProperties:false` on every object, so open-key records can't be generated directly — the clinical generator asks for `pathophys` as an array of `{symptom, mechanism}` pairs (converted to the record in code) and fills `examination.other` with `{}`.
- **2026-08-13 · Target diagnosis is picked in code, not by the model.** `scripts/diagnosis-pool.ts` holds a per-system, KZN-weighted pool (common/uncommon, with topic-match keywords); the generator excludes bank+drafts diagnoses up front and pins the pick in the prompt — no generation is ever wasted on a dedupe collision. Pool exhausted → the run stops early with a message.
- **2026-08-13 · Phase 2 session engine is deterministic; the Brain is a port.** `lib/session-engine.ts` owns disclosure gating (trigger match: word-boundary + stem tolerance), exam-step → findings narration, verbatim investigation results (stimulusRef pauses into an interpret-step), phase transitions, speaker arbitration, bank triggers, the 20:00/7:00 timers (accumulated ACTIVE seconds — away-time after quit never counts), nudges and warnings. `BRAIN=mock|live` (default mock) picks the Brain: MockBrain is fully deterministic (template patient speech, verbatim examiner lines, a real computed MarkingReport from the tracked logs) so the whole flow runs and is tested at $0 (`pnpm simulate`); AnthropicBrain (haiku patient w/ padded cached rules block, sonnet-5 examiner follow-ups + single structured-outputs marking call) is code-complete and awaits API budget.
- **2026-08-13 · Session persistence: STORE=file|supabase, default file.** `.sessions/*.json` (gitignored) for dev; `st_sessions (id text pk, data jsonb, updated_at)` via `SUPABASE_URL`+`SUPABASE_SECRET_KEY` for prod — DDL in `supabase/schema.sql`. New env vars: `BRAIN`, `STORE`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`.
- **2026-08-13 · /session reuses the /admin/review cookie gate** (single user, single password); `/api/admin/login` now accepts a same-site `next` path so both pages can bounce back after login. The client only ever receives a redacted SessionView — the hidden case JSON never ships to the browser.
